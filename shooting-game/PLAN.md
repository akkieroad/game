# シューティングゲーム開発計画書 — 「NEON DRIFT / ネオンドリフト」

HTML / CSS / JavaScript のみで動作する、ブラウザで即起動できるオリジナル・シューティングゲームの設計・実装計画。
外部ライブラリは原則不使用（バニラJS）。必要な箇所のみ理由を明記して採用する。

---

## 1. 概要

### コンセプト
**「NEON DRIFT（ネオンドリフト）」** — 縦スクロール型トップビュー・シューティング。
プレイヤーはネオン光の宇宙船を操り、押し寄せる敵編隊を撃破しながら5ステージのボスを攻略する。
グラフィックは Canvas2D による発光（グロー）表現で統一し、レトロアーケードと現代的ネオンUIを融合させる。

### テーマ
- **ビジュアル**: サイバー／ネオン。暗い宇宙空間に鮮やかなシアン・マゼンタ・イエローの発光体。
- **サウンド**: チップチューン風BGM＋パンチの効いたSE。
- **プレイ感**: 30秒でルールが分かり、10分で1周でき、繰り返しスコアを伸ばしたくなる。

### 他のシューティングとの差別化ポイント
1. **「ドリフト・ブースト」機構** — 短時間だけ機体を高速移動させ、その残像（軌跡）が弾除け判定を持たない“無敵回避”になる独自アクション。攻めと回避の駆け引きが生まれる。
2. **チェイン・スコアリング** — 敵を途切れず連続撃破するほど倍率が上がる連鎖ボーナス。撃ち漏らすと倍率リセット。単なる撃破数でなく“流れ”を評価する。
3. **手続き生成 ＋ 難易度アダプティブ** — 敵編隊は乱数シードで生成し、プレイヤーの被弾頻度に応じて敵密度・弾速を自動調整（後述 DDA）。
4. **完全ゼロ依存・単一フォルダ配布** — `index.html` を開くだけで即起動。ビルド不要、CDNもオプション扱い。
5. **入力の完全両対応** — キーボード / マウス / タッチ / ゲームパッドを最初から統一設計し、モバイルでも快適。

## 2. ゲーム設計

### プレイヤー操作
| 入力手段 | 移動 | ショット | ブースト（回避） | ボム／特殊 |
|---|---|---|---|---|
| キーボード | 矢印 / WASD | Z or Space（押し続けで連射） | Shift | X |
| マウス | ポインタ追従 | 左クリック長押し | 右クリック | 中クリック |
| タッチ | ドラッグで機体追従 | 自動連射 | 画面右下ボタン | 画面左下ボタン |
| ゲームパッド | 左スティック/十字 | A | RB | B |

- **自動連射のオプション**（モバイル既定ON）と手動連射を設定で切替。
- ブーストはクールダウン制（例: 発動0.4秒＋クールダウン2秒）。ゲージUIで残量可視化。

### 敵の挙動（ビヘイビア）
敵は「移動パターン」と「攻撃パターン」を分離したデータ駆動設計にする。

- **Straight（直進兵）**: 画面上から下へ等速。最も基本。
- **Sine（波動兵）**: 正弦波で左右に揺れながら降下。
- **Homing（追尾兵）**: プレイヤー方向へ緩やかに旋回。数を絞って登場。
- **Turret（砲台）**: 画面端に停留し、自機狙い弾を周期発射。
- **Formation（編隊）**: 複数機がフォーメーションを組み、一体崩すと隊列が乱れる。
- **Boss（ボス）**: HPバー付き。フェーズ制で攻撃パターンが変化（弾幕→レーザー→突進）。

各敵は `type / hp / speed / scoreValue / movePattern / firePattern / spawnTime` を持つJSON的テーブルで定義。

### ステージ進行
- **全5ステージ**。各ステージ = 「ウェーブ（雑魚編隊）× 数回 → 中ボス（任意） → ボス」。
- ステージは **タイムライン（出現スケジュール）** で管理。`{ time, enemyType, x, count, interval }` の配列を時系列で消化。
- ステージ間に短いインターミッション（スコア小計・機体回復チャンス）。
- 5ステージクリアで **エンドレスモード**（無限ウェーブ＋難易度上昇）へ移行可能。

### スコアシステム
- 基本点: 敵種別ごとの `scoreValue`。
- **チェイン倍率**: 連続撃破でx1→x2→…最大x8。一定時間（1.5秒）撃破が途切れると倍率リセット。
- **かすりボーナス（グレイズ）**: 敵弾を至近距離で回避すると微小加点＋ブーストゲージ回復。上級者への報酬。
- **ノーミス／ノーボムボーナス**: ステージ終了時に加算。
- **ハイスコア**: `localStorage` に保存し、タイトルとリザルトで表示（上位5件）。

### ライフ / 体力機構
- **ライフ制（残機）**: 初期3機。被弾で1機減、機体は短時間無敵で復帰。
- **シールド（HP）併用**: 各機に小さなシールド（2ヒットまで吸収）を持たせ、理不尽な即死を緩和。
- **ボム／特殊**: 画面全体の敵弾消去＋大ダメージ。所持数制（初期2）。
- 残機0で **ゲームオーバー** → リザルト画面。ステージ途中コンティニュー（スコア半減）を任意で用意。

## 3. UI / UX

### ビジュアルエフェクト
- **グロー表現**: Canvas の `shadowBlur` / `shadowColor`、または加算合成 `globalCompositeOperation = 'lighter'` でネオン発光。
- **パーティクル**: 爆発、弾着、ブースト残像、背景の流れ星をオブジェクトプールで管理。
- **画面演出**: 被弾時のスクリーンシェイク、ボム発動時のフラッシュ、チェイン更新時の倍率ポップ。
- **背景**: 多層パララックス（遠景の星、近景のグリッド）でスクロール感を演出。

### レスポンシブ・レイアウト戦略
- **論理解像度固定＋スケーリング**: 内部ゲーム座標は `900×1600`（縦長）などに固定。表示は CSS で `object-fit: contain` 相当のスケール計算を行い、`devicePixelRatio` を掛けて高DPI対応。
- **セーフエリア**: `env(safe-area-inset-*)` を考慮しノッチ端末でUIが隠れないよう配置。
- **入力レイヤーの切替**: 画面幅／ポインタ種別（`matchMedia('(pointer: coarse)')`）でタッチUI（仮想ボタン）表示を自動判定。
- **向き対応**: 縦持ち推奨。横持ち時はレターボックス＋「縦持ち推奨」オーバーレイを表示。
- CSSは `clamp()` / `vmin` を活用し、HUD文字やボタンを画面サイズに追従させる。

### オーディオ・フィードバック
- **Web Audio API** で低遅延SE再生（`AudioBufferSourceNode`）。HTMLAudioより遅延・同時再生に強い。
- BGMはループ、SEはショット／爆発／被弾／チェイン／ボス警告など。
- **触覚フィードバック**: 対応端末で `navigator.vibrate()` を被弾・ボム時に短振動。
- **アクセシビリティ**: 音量スライダー（BGM/SE個別）、ミュート、色覚配慮の弾色、画面点滅を抑える「フラッシュ軽減」オプション。
- **初回タップでオーディオ解錠**: モバイルの自動再生制限に対応し、タイトル画面のユーザー操作で `AudioContext.resume()`。

## 4. 実装

### HTML構造（骨子）
```html
<div id="game-root">
  <canvas id="game-canvas"></canvas>        <!-- 描画本体 -->
  <div id="hud">                            <!-- スコア・残機・ゲージ（DOM重ね） -->
    <div id="score"></div>
    <div id="lives"></div>
    <div id="boost-gauge"></div>
  </div>
  <div id="touch-controls" hidden>          <!-- モバイル用仮想ボタン -->
    <button id="btn-boost"></button>
    <button id="btn-bomb"></button>
  </div>
  <div id="overlay">                         <!-- タイトル/ポーズ/リザルト -->
    <!-- 画面ごとにJSで切替 -->
  </div>
</div>
```
- 描画は Canvas、HUD/メニューは DOM。テキスト・ボタンはDOMの方が保守・アクセシビリティで有利。

### CSS / アニメーション方針
- レイアウトは Flexbox / Grid。HUDは `position: absolute` でCanvasに重ねる。
- メニュー遷移・ポップは CSS transition / `@keyframes`（GPU合成される `transform` / `opacity` 中心、`will-change` 指定）。
- ゲーム内の激しい動きは Canvas 側で処理し、DOMアニメは軽量な演出に限定。
- カスタムプロパティ（`--accent` 等）でテーマ色を一元管理。

### JavaScript ロジック
**モジュール分割（ES Modules）**
- `main.js`: 起動・画面遷移・全体統括。
- `engine/loop.js`: ゲームループ。
- `engine/input.js`: 入力の正規化（キー/マウス/タッチ/パッド → 共通コマンド）。
- `engine/audio.js`: Web Audio 管理・プリロード。
- `entities/`: player, enemy, bullet, particle, boss。
- `systems/`: spawn（ステージ管理）, collision, scoring, difficulty。
- `ui/`: hud, menus。

**ゲームループ（固定タイムステップ推奨）**
```js
let last = performance.now(), acc = 0;
const STEP = 1000 / 60;               // 物理は60Hz固定
function frame(now) {
  acc += now - last; last = now;
  while (acc >= STEP) { update(STEP); acc -= STEP; }  // 更新を分離
  render(acc / STEP);                  // 補間して描画
  requestAnimationFrame(frame);
}
```
- 固定ステップにより端末リフレッシュレート差（60/120Hz）で挙動が変わらない。
- `document.hidden` でタブ非表示時はポーズ（`visibilitychange`）。

**イベントハンドラ**
- `keydown/keyup` はキー状態を Set/Map に保持（押しっぱなし対応）。
- `pointerdown/move/up` に統一（マウス・タッチを一本化）。`touch-action: none` でスクロール抑止。
- `gamepadconnected` でパッド有効化、毎フレーム `navigator.getGamepads()` をポーリング。
- リスナは `{ passive: false }` を適切に指定。

**当たり判定**
- 基本は **円判定**（中心間距離² ≤ 半径和²、平方根回避）。自機の被弾判定は小さめ（“食らい判定”を機体より小さく）にして理不尽さを軽減。
- 弾が大量になるため **空間分割（グリッド／簡易ビニング）** で総当たりを回避。画面を格子に分け、同一・近傍セルのみ判定。
- すべてのエンティティは **オブジェクトプール** で再利用しGC負荷を抑制。

**難易度調整（DDA: Dynamic Difficulty Adjustment）**
- プレイヤーの直近パフォーマンス指標（被弾間隔・チェイン維持率・残機）を移動平均で監視。
- 良好 → 敵密度・弾速・出現頻度を段階的に上げる／苦戦 → 緩和。上下限をクランプして破綻を防止。
- 加えて **難易度プリセット**（EASY/NORMAL/HARD）を基準倍率として用意し、DDAはその周辺で微調整。

**スコア管理**
- `ScoreSystem` がチェイン倍率・グレイズ・ボーナスを集約。
- ハイスコアは `localStorage`（JSON）で永続化。破損時フォールバック。

## 5. アセット管理とパフォーマンス

### 画像最適化
- **スプライトシート（テクスチャアトラス）** に統合し、リクエスト数と切替コストを削減。
- 形式は **WebP**（フォールバックPNG）。ネオンは単色＋グローで描けるものは画像レスにしてCanvas描画（アセット削減）。
- 解像度は表示上限に合わせて用意（過剰な大画像を避ける）。

### オーディオ最適化
- SEは短い **OGG/MP3** を Web Audio でデコードしバッファ保持。BGMはストリーミング可。
- 同一SEの多重再生はソースノードを都度生成（バッファは共有）。

### プリロード技術
- タイトル画面で **ローディングバー**を表示し、画像（`Image` / `createImageBitmap`）と音声（`decodeAudioData`）を並列プリロード。全完了までゲーム開始をブロック。
- `Promise.all` で読み込み集約。失敗時リトライ／代替表示。
- 必要なら `<link rel="preload">` で初期アセットを先読み。

### パフォーマンス考慮
- **オブジェクトプール**で生成/破棄を抑制（弾・敵・パーティクル）。
- **オフスクリーンCanvas**（`OffscreenCanvas` 対応時）で背景・静的レイヤーを事前描画。
- `shadowBlur` は重いので、多用箇所は事前レンダリング済みグローテクスチャで代替。
- 描画はレイヤー分割し、変化しない背景は再描画頻度を落とす。
- `requestAnimationFrame` 準拠、`setInterval` は使わない。
- パーティクル総数・敵弾総数に上限を設け、超過時は間引き。
- FPS計測を開発時HUDに表示し、低スペック端末で自動的にエフェクト品質を落とす“クオリティ・スケーリング”。

## 6. テストと展開

### クロスブラウザ再現性テスト
- 対象: 最新の Chrome / Edge / Firefox / Safari（デスクトップ）、iOS Safari / Android Chrome（モバイル）。
- 確認項目: 描画、入力（タッチ/パッド）、オーディオ解錠、`localStorage`、高DPIスケーリング、向き変更。
- Playwright（開発時のみ／配布物には含めない）で主要フロー（起動→1ステージ→リザルト）を自動スモークテスト。採用理由: 実ブラウザ横断の回帰確認を自動化できるため（本番ランタイムには非同梱）。

### デバッグTips
- **デバッグモード**（URLに `?debug=1`）で当たり判定円、FPS、エンティティ数、現在シード、DDA係数を可視化。
- 決定的再現のため乱数は **シード付き擬似乱数**（例: mulberry32）を使い、バグ再現時に同一シードでリプレイ。
- `try/catch` とグローバル `error` / `unhandledrejection` ハンドラでクラッシュをHUDに表示。
- ステップ実行（1フレーム送り）用ホットキーを開発ビルドに用意。

### ブラウザ展開ガイド
- **即時ローカル起動**: `index.html` をダブルクリック。※ES Modules / `fetch` はローカルファイルでCORS制限があるため、開発時は簡易サーバ（`python -m http.server` 等）推奨。配布はモジュールを1ファイルにバンドル or `type="module"` を避けたクラシックスクリプト構成も選択可。
- **静的ホスティング**: GitHub Pages / Netlify / Cloudflare Pages にフォルダをアップロードで公開。ビルド不要。
- キャッシュ制御: アセットにバージョンクエリ（`?v=1.0`）を付与し更新反映。
- 任意で **PWA化**（`manifest.json` ＋ Service Worker）しオフライン起動・ホーム画面追加に対応。

## 7. フルファイル構成案

即ブラウザ読込可能な単一フォルダ構成。`index.html` を起点にすべて相対パス参照。

```
shooting-game/
├── index.html              # エントリ。Canvas/HUD/overlay の骨組みと <script type="module"> 読込
├── style.css               # レイアウト・HUD・メニュー・レスポンシブ・テーマ変数
├── README.md               # 操作説明・ルール・スコア仕様・起動/テスト手順（下記参照）
├── manifest.json           # (任意) PWA メタ情報
├── sw.js                   # (任意) Service Worker（オフライン対応）
│
├── js/
│   ├── main.js             # 起動・画面遷移・全体統括
│   ├── config.js           # ゲーム定数（解像度・難易度プリセット・パラメータ）
│   ├── engine/
│   │   ├── loop.js         # 固定タイムステップのゲームループ
│   │   ├── input.js        # キー/マウス/タッチ/パッドを共通コマンドに正規化
│   │   ├── audio.js        # Web Audio ラッパ・プリロード・再生
│   │   ├── assets.js       # 画像/音声のプリロードとローディングバー
│   │   ├── rng.js          # シード付き擬似乱数（再現性）
│   │   └── pool.js         # 汎用オブジェクトプール
│   ├── entities/
│   │   ├── player.js
│   │   ├── enemy.js        # 敵の移動/攻撃パターン（データ駆動）
│   │   ├── boss.js
│   │   ├── bullet.js
│   │   └── particle.js
│   ├── systems/
│   │   ├── spawn.js        # ステージタイムライン・ウェーブ管理
│   │   ├── collision.js    # 空間分割＋円判定
│   │   ├── scoring.js      # チェイン倍率・グレイズ・ハイスコア(localStorage)
│   │   └── difficulty.js   # DDA（動的難易度調整）
│   └── ui/
│       ├── hud.js          # スコア/残機/ゲージ更新
│       └── menus.js        # タイトル/ポーズ/リザルト/設定
│
└── assets/
    ├── images/
    │   └── sprites.webp    # スプライトアトラス（PNGフォールバック可）
    ├── audio/
    │   ├── bgm/            # ステージ/ボスBGM（ogg/mp3）
    │   └── sfx/            # ショット/爆発/被弾/チェイン等
    └── data/
        └── stages.json     # 各ステージの出現スケジュール（データ駆動）
```

### 各ファイルの役割（要点）
- **index.html**: DOM骨格のみ。ロジックは全てモジュールに委譲。`<noscript>` 案内も記載。
- **style.css**: テーマ変数・レスポンシブ・HUD/タッチUI。ゲーム内演出はCanvas側なのでCSSは最小限。
- **config.js / stages.json**: 数値・出現データを分離し、コード変更なしでバランス調整可能に。
- **README.md（納品ドキュメント）**: 以下を必ず含める。
  - **操作説明**: 各入力手段の操作表。
  - **ルール**: 目的・ステージ構成・ライフ/ブースト/ボムの説明。
  - **スコア仕様**: 基本点・チェイン倍率・グレイズ・ボーナス・ハイスコア保存。
  - **起動手順**: ローカル起動（簡易サーバ推奨の理由）・ホスティング手順。
  - **テスト手順**: 対応ブラウザ一覧、`?debug=1` の使い方、スモークテスト実行方法、既知の制限。
  - **設定**: 音量・難易度・フラッシュ軽減などのアクセシビリティ項目。

### 外部ライブラリ方針
- **既定はゼロ依存（バニラJS）** — 即起動・軽量・学習容易さを優先。
- 採用を検討し得るもの（いずれも任意・理由必須）:
  - **Playwright**: 開発時のクロスブラウザ自動テストのみ（配布物非同梱）。
  - **Howler.js**: Web Audio の実装コストを下げたい場合の代替。ただし自前 `audio.js` で十分なため既定は不採用。
- CDN依存は「即オフライン起動」を損なうため、採用時もローカル同梱を基本とする。

## マイルストーン（実装順の目安）
1. 骨組み（HTML/CSS/Canvas）＋ゲームループ＋入力正規化 → 自機が動く。
2. 弾・敵・当たり判定・オブジェクトプール → 撃って倒せる。
3. スコア/チェイン/HUD/ライフ → 遊びが成立。
4. ステージタイムライン＋ボス → 1周できる。
5. エフェクト/オーディオ/レスポンシブ/タッチUI → 体験の質。
6. DDA・難易度プリセット・ハイスコア保存 → リプレイ性。
7. テスト（クロスブラウザ）・README・(任意)PWA → 展開。
